**Goal:** Reference Dockerfiles, a runnable compose control-plane demo and plain Kubernetes manifests for the five gsp binaries, smoke-tested in CI.

**Architecture:** One multi-target `deploy/Dockerfile` (shared `rust:1-trixie` builder → five `distroless/cc-debian13:nonroot` runtime targets, plus a `node` stage for the UI). `deploy/smoke.sh` is the single test: it drives a running compose stack over HTTP and is used by both `make deploy-smoke` and a new `deploy` CI job. Manifests are validated with `kubeconform` (schema only).

**Tech Stack:** Docker / Compose v2, distroless, POSIX `sh` + `curl`, `kubeconform`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-01-deploy-design.md`

## Global Constraints

- Reference only: images are built and tested, **never published or pushed**.
- Runtime base `gcr.io/distroless/cc-debian13:nonroot` (uid 65532); builder `rust:1-trixie`; UI stage `node:22`.
- Builder must not copy `rust-toolchain.toml` and sets `RUSTUP_TOOLCHAIN=stable`.
- `[profile.release]` gains `strip = true`.
- No shell/curl in runtime images: health is probed from outside (smoke script, k8s `httpGet`).
- Control-plane binaries default to `127.0.0.1`; every container command passes `--listen 0.0.0.0:<port>`.
- UI has no `/healthz`; use `GET /ui/session`. gsp admin `/healthz` is exempt from its bearer token.
- `gsp --controller` **bails at startup if the controller has no config**, so the seed step must complete first.
- No secrets in committed YAML except clearly marked placeholders; `.env` is already git-ignored.
- AGENTS.md: `cargo fmt --all` then `make check` before any commit touching Rust/Cargo; commit directly on `main`, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; **do not push**.

## Deviations from the spec (apply in Task 6)

1. Compose `gsp` uses host networking, so it cannot resolve bridge service names. `controller` and `aggregator` therefore also publish **on host loopback** (`127.0.0.1:9901`, `127.0.0.1:9902`) and `gsp` dials `http://127.0.0.1:…`. The spec said "only the UI port is published".
2. CI uses `docker compose up -d` plus polling in `smoke.sh`, not `up --wait` (a one-shot `seed` service that exits does not play well with `--wait`).
3. The k8s `gsp` config is a `Secret`, not a `ConfigMap`: for a `hostNetwork` pod the kubelet probes the node IP, so the admin listener must bind `0.0.0.0` and carries an `auth_token`.

## Review Focus

- Controller data dir unwritable by uid 65532 (named volume / PVC ownership) → controller crash-loops. Pinned by Task 2 smoke (a config write must succeed) and `fsGroup` in Task 4.
- glibc mismatch builder vs runtime → binary fails to start. Pinned by Task 1 (`--version` on every image).
- `gsp` starts before the config is seeded → exits. Pinned by Task 2 (`depends_on: service_completed_successfully`; smoke fails if `gsp` is not reported).
- `.env` missing or token empty → services run open without anyone noticing. Pinned by Task 2 (`${VAR:?}` makes compose refuse to start).
- A hostNetwork pod resolving cluster DNS names (`aggregator` URL) fails. Pinned by `dnsPolicy: ClusterFirstWithHostNet` in Task 4.

#   docker build -f deploy/Dockerfile --target gsp-controller -t gsp-controller .

# --- frontend (only the gsp-ui target uses it) ---------------------------
FROM node:22-bookworm-slim AS web

`deploy/smoke.sh`:

```sh
#!/bin/sh
# Smoke test for deploy/compose: assumes `docker compose up -d` already ran.
# Polls (services start asynchronously), so it is safe to run immediately.
set -eu
ENV_FILE="${COMPOSE_ENV_FILE:-deploy/compose/.env}"
# shellcheck disable=SC1090
. "$ENV_FILE"

fail() { echo "SMOKE FAIL: $*" >&2; exit 1; }

# retry <desc> <cmd...> — up to 60 s
retry() {
  desc=$1; shift
  i=0
  until "$@" >/dev/null 2>&1; do
    i=$((i + 1))
    [ "$i" -ge 60 ] && fail "$desc (gave up after 60 s)"
    sleep 1
  done
  echo "ok: $desc"
}

CTRL=http://127.0.0.1:9901
AGG=http://127.0.0.1:9902
UI=http://127.0.0.1:9903
GSP_ADMIN=http://127.0.0.1:9900

retry "controller /healthz" curl -fsS "$CTRL/healthz"
retry "aggregator /healthz" curl -fsS "$AGG/healthz"
retry "gsp admin /healthz" curl -fsS "$GSP_ADMIN/healthz"
retry "ui /ui/session" curl -fsS "$UI/ui/session"

# The seed step wrote revision 1 and gsp pulled it.
retry "controller serves the seeded config" \
  curl -fsS -H "Authorization: Bearer $GSP_CONTROLLER_TOKEN" "$CTRL/config"

# gsp pushed its state to the aggregator (proves --controller + --aggregator
# wiring and the aggregator token end to end).
fleet_has_gsp() {
  curl -fsS -H "Authorization: Bearer $GSP_AGGREGATOR_TOKEN" "$AGG/fleet/pools" |
    grep -q '"instance"'
}
retry "aggregator reports the gsp instance" fleet_has_gsp

# UI login works with the configured password.
ui_login() {
  curl -fsS -X POST -H 'content-type: application/json' \
    -d "{\"password\":\"$GSP_UI_PASSWORD\"}" "$UI/ui/login"
}
retry "ui login" ui_login

# A wrong token must be refused (the gate is actually on).
code=$(curl -s -o /dev/null -w '%{http_code}' -H 'Authorization: Bearer wrong' "$CTRL/config")
[ "$code" = 401 ] || fail "controller accepted a wrong token (HTTP $code)"
echo "ok: controller rejects a wrong token"

echo "SMOKE PASS"
```

# gsp (host networking, docs/12's default for an edge process) that pulls its
# config from the controller and pushes state to the aggregator.
# Tokens come from .env; `${VAR:?}` refuses to start if one is unset.
# NB: tokens appear in `docker inspect` — fine for a demo; use Docker/K8s
# secrets in production.
name: gsp-demo

x-build: &build
  context: ../..
  dockerfile: deploy/Dockerfile

services:
  controller:
    build: { <<: *build, target: gsp-controller }
    image: gsp-deploy/gsp-controller:local
    command:
      - --listen=0.0.0.0:9901
      - --data-dir=/data
      - --auth-token=${GSP_CONTROLLER_TOKEN:?set GSP_CONTROLLER_TOKEN in .env}
    ports: ["127.0.0.1:9901:9901"]   # gsp (host network) dials it here
    volumes: ["controller-data:/data"]
    restart: unless-stopped

  aggregator:
    build: { <<: *build, target: gsp-aggregator }
    image: gsp-deploy/gsp-aggregator:local
    command:
      - --listen=0.0.0.0:9902
      - --auth-token=${GSP_AGGREGATOR_TOKEN:?set GSP_AGGREGATOR_TOKEN in .env}
    ports: ["127.0.0.1:9902:9902"]
    restart: unless-stopped

  ui:
    build: { <<: *build, target: gsp-ui }
    image: gsp-deploy/gsp-ui:local
    command:
      - --listen=0.0.0.0:9903
      - --ui-password=${GSP_UI_PASSWORD:?set GSP_UI_PASSWORD in .env}
      - --controller-url=http://controller:9901
      - --controller-token=${GSP_CONTROLLER_TOKEN}
      - --aggregator-url=http://aggregator:9902
      - --aggregator-token=${GSP_AGGREGATOR_TOKEN}
    ports: ["127.0.0.1:9903:9903"]
    depends_on: [controller, aggregator]
    restart: unless-stopped

  seed:
    image: curlimages/curl:8.11.1
    command:
      - -fsS

      - --retry-delay=1
      - --retry-all-errors
      - -X

      - --data-binary
      - "@/gsp.yaml"
      - http://controller:9901/config

    restart: "no"

    build: { <<: *build, target: gsp }

      - --aggregator=http://127.0.0.1:9902
      - --aggregator-token=${GSP_AGGREGATOR_TOKEN}

    restart: unless-stopped

volumes:
  controller-data:
