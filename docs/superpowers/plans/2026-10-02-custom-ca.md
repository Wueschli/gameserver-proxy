**Goal:** Every fleet binary accepts `--ca-file <PEM>` and trusts those CAs, on top of the built-in Mozilla roots, for all outbound HTTPS.

**Architecture:** A new reqwest-only crate `wayhouse-http` holds a set-once global list of extra root certificates and is the single place production HTTP clients get built (`builder()` / `client()`). Each binary's `main` calls `wayhouse_http::init_ca_file` when the flag is given; every production `reqwest::Client::new()/builder()` in the five binaries switches to the helper.

**Tech Stack:** Rust, reqwest 0.12.28 (`rustls-tls`), tokio-rustls 0.26 (tests), rustls-pki-types PEM parsing (tests), clap 4.

**Spec:** `docs/superpowers/specs/2026-10-02-custom-ca-design.md`

## Global Constraints

- Flag name and help text, verbatim on all five binaries: `--ca-file <PATH>` — "PEM file of extra CA certificates to trust for outbound HTTPS, in addition to the built-in Mozilla roots".
- Additive: the built-in webpki roots are never disabled.
- `wayhouse-http` depends only on `reqwest` + `thiserror` (dev-deps may add tokio / tokio-rustls / rustls-pki-types). Never on `wayhouse-core` / `wayhouse-config`.
- Every `CaError` message starts with `--ca-file <path>: ` (except `AlreadyInitialised`).
- Call sites keep "fresh client where there was one" semantics — no new shared/global `Client`.
- No `unsafe`; `make check` green before each commit; `cargo fmt --all` as its own step first.

## Review Focus

1. A bundle with several certificates (e.g. an unrelated cert before the CA) — every cert must be trusted, not just the first. → Task 1 `trusts_every_cert_in_a_bundle`.
2. A combined PEM holding a private key next to the cert (common `cat key crt > ca.pem` mistake) — the key is ignored, the cert loads. → Task 1 `ignores_non_certificate_pem_sections`.
3. PEM-armoured garbage (valid base64 that is not X.509) — must fail at startup, not at the first request. → Task 1 `rejects_a_malformed_certificate`.
4. `--ca-file` set while talking to plain `http://` endpoints — nothing changes (HA/adopt stay `http://`). → covered by the existing fleet tests passing unchanged with no flag; Task 3 spawns the controller over plain HTTP behind the terminator.
5. The flag silently accepted but not wired in one binary. → Task 2 `every_binary_rejects_a_missing_ca_file`.
