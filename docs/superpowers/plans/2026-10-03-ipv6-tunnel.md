# IPv6 Tunnel Networks and IPv6 Underlay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `gsp-controller` allocates tunnel addresses from an IPv6 network as well as an IPv4 one, agents and proxies route IPv6 peers, WireGuard runs over an IPv6 underlay, and a changed network is refused at startup unless `--tunnel-readdress` is given.

**Architecture:** Generalize the existing address book (`Network` becomes family-aware with `u128` arithmetic, addresses become `IpAddr`); no second book, no wire or storage format change. Clients build host routes with `IpAddrMask::host`. The netns lab gains IPv6 links so the e2e suite runs on an IPv6 tunnel network by default, plus IPv4-tunnel, IPv6-underlay and network-change scenarios.

**Tech Stack:** Rust, sled, axum, `defguard_wireguard_rs` 0.12 (kernel + boringtun), the rootless netns lab in `gsp-fleet-tests`.

**Spec:** `docs/superpowers/specs/2026-10-03-ipv6-tunnel-design.md`

## Global Constraints

- IPv4 `--tunnel-network` rules unchanged: prefix `/16` to `/30`.
- IPv6 `--tunnel-network` prefix `/64` to `/120`; shorter than `/64` is refused saying the pool is a single subnet.
- Host 0 (network / `…::`) and the all-ones address are never allocated or pinnable in either family.
- `MAX_ENTRIES = 65_534` for both families; `capacity = min(host count, MAX_ENTRIES)`.
- Storage format unchanged: `Assignment` stays JSON; `by_address` keys stay raw octets (4 or 16 bytes). A database written by today's code must reopen with its entries.
- Wire format unchanged; `tunnel_address` / `tunnel_network` may hold IPv6 text.
- IPv6 backends use the bracketed `SocketAddr` form `[addr]:port`.
- Example / lab / deploy tunnel network: `fd49:89c1:4b5e:60::/64`.
- `make check` green after every task; IPv4 behaviour unchanged after every task.
- Install `protoc` before `make check` in the cloud environment (HANDOVER).
- Comments at the density of the surrounding code; module `//!` docs updated where a module's scope changes.

## Review Focus

1. **Non-canonical IPv6 text** (`fd49:0::5` vs `fd49::5`, upper-case hex) in a pin, a backend or a saved address file must be treated as the same address everywhere it is compared. Tests in Tasks 2 and 4.
2. **A pin of the other family** (IPv4 pin on an IPv6 network and vice versa) must be a clear `422`, never a panic or a silent grant. Test in Task 2.
3. **Re-address on boringtun:** the same pubkey arriving with a new `/128` must take the remove-then-configure path, not panic. Covered by the Task 5 network-change scenario on both backends in CI.
4. **A refused startup must change nothing:** no listener bound, no address book write. Test in Task 3.
5. **Prefix bounds:** `/64`, `/120`, `/16`, `/30` and one step outside each, with host bits set in the input. Tests in Task 1.

  - `pub fn check_network_change(book: &AddressBook, readdress: bool) -> Result<Vec<Entry>, String>`: `Err` (message below) when entries exist and `!readdress`; `Ok(entries)` otherwise (main logs one `WARN` with the count and up to ten `role name address` when non-empty).

  - `claim`: an existing owner whose address is not a host of the configured network is re-addressed: treat it as a new owner (pin rules or lowest free), remove the old `by_address` key in the same transaction, reset `first_seen` to `now`, and `tracing::info!` role, name, old and new address. This branch is unconditional because without the flag the controller never starts with such entries.

Error message (exact first line, then up to ten entries, one per line):
`--tunnel-network {network} does not contain {n} stored tunnel address(es); restore the previous --tunnel-network, or pass --tunnel-readdress to move these peers to the new network at their next registration`
